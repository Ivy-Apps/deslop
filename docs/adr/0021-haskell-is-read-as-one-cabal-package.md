# 21. Haskell is read as one cabal package

Date: 2026-10-24

## Status

Accepted. The second language behind
[ADR 20](0020-languages-plug-in-through-a-staged-compiler-frontend.md)'s
`CompilerFrontend`, and the first whose names need its naming obligations.

## Context

Deslop is written in Haskell, and its own layering
([ADR 13](0013-the-source-tree-is-layered-by-dependency-direction.md)) was
checked by a `grep` because Deslop could not read Haskell. A Haskell frontend
has to answer questions TypeScript never asked:

- **Which file is `Deslop.Module`?** Not a question about the file system:
  GHC looks a module up in the source directories of the component compiling
  the importer, then in the libraries that component depends on. Two
  components may each have a `Utils`; an import means the importer's own.
- **What is a file called?** Every executable, test suite and benchmark has a
  `Main`. A Problem ID is built from the canonical name, so two `Main`s sharing
  it would share every Baseline entry.
- **What is in a file?** CPP, `-F -pgmF` preprocessors and literate Haskell
  mean the bytes on disk are not what GHC compiles. Layout means an import is
  delimited by columns, not by a terminator.
- **What is the project?** A `.cabal` file, possibly several behind a
  `cabal.project`, possibly generated by hpack or driven by stack, with
  `common` stanzas and `if` branches.

## Decision

**Scope: what the Rules DSL needs, no more.** A file lowers to one Module with
an `ImportEdge` per import and a `ReExportEdge` per import a `module X` export
item names - every import whose alias, or whose own name when it has none, is
`X`. `module M` in `M`'s own export list is no edge. Import lists, `hiding`
and qualification are kept in the tokens and never interpreted: no Rule reads
symbols. There are no built-in lints; `builtInRules` is empty.

**The project is one package, read with Cabal's own parser.** `detect` looks
for exactly one `*.cabal` file at the root, without parsing it. `loadConfig`
reads it with `Cabal-syntax`'s `parseGenericPackageDescription` - a GHC boot
package, so no new transitive dependency - which resolves `common` stanzas the
way `cabal` does. Every component's conditional branches are taken at once
(`ignoreConditions` per component, in `.cabal` order): a Rule should hold in
every build, not only in the one on this machine. A root `cabal.project` is
accepted only when its `packages:` names that same package (`.` or the
`.cabal` file); anything else is a `ConfigError` naming the other packages.
hpack-only and stack-only projects are not read.

**Names, canonical first.** Every Module Name is slash-spelled
([ADR 19](0019-module-names-are-slash-segmented-in-every-language.md)), inside
the project and out (`External Data/Text`).

- **A module's canonical name is always component-qualified:
  `<kind>/<component>/<Name>`**, with kinds `lib`, `exe`, `test` and `bench`;
  the main library is named after its package, a sub-library after itself.
  `lib/deslop/Deslop/Module`, `test/deslop-test/Frontend/TypeScriptSpec`, and
  for a component's `main-is`, `exe/deslop/Main`, `test/deslop-test/Main`,
  `bench/deslop-bench/Main`.
- **Every canonical name starts with `lib/`, `exe/`, `test/` or `bench/` and
  its component, so canonical names never clash**: a library's `Utils` and a
  test suite's are `lib/p/Utils` and `test/p-test/Utils`, and every
  executable's `Main` is its own. Only two source directories of one component
  holding the same path can claim one name - GHC rejects that import as
  ambiguous - and a `LowerError` names the files.
- Reports and Baseline ids show the qualified name: a Problem id is
  `layering#core-is-language-agnostic#lib/deslop/Deslop/Module`.
- The bare GHC name, `Deslop/Module` or `Main`, is kept as an alias, and a
  Rule matches a module by any of its names: write `Deslop/**` for the module
  whatever compiles it, or `lib/*/Frontend/{{LanguageName}}/**` to leave a
  test suite's `Frontend/TypeScriptSpec` alone.
- The `ModuleId` is the canonical absolute path, as in TypeScript.

**Discovery and ownership.** `discover` walks every component's
`hs-source-dirs` (`.` when there are none) for `.hs` files, honouring the
`GitIgnore` and `Frontend.Haskell.Ignore` (`dist-newstyle`, `dist`,
`.stack-work`, `.hie`, `.hpc`, `.cabal-sandbox`). A file is owned by the
component whose `main-is` it is; otherwise by the component with the deepest
source directory containing it, the first in the `.cabal` file on a tie. It is
named by its path below that directory, as GHC searches. A `module` header
naming anything else is a `LowerError` - Deslop goes by the path, as GHC's
lookup does - except for a `main-is`, which is `Main` whatever it says.

**Resolution.** A component sees its own modules first, then the modules of
the project libraries its `build-depends` names - `p` for the main library,
`p:sub` or a bare `sub` for a sub-library. A library sees only its own and the
libraries it names. Everything else is `External` under its slashed name,
including `Paths_*`. A package import names another package and is `External`,
except `"this"`, which is the importing component, and the package's own name,
which is what that component sees.

**The parser is a lossless island grammar.** A Megaparsec lexer makes tokens
of everything - nested `{- -}`, `{-# #-}` pragmas, strings, character
literals, a byte-order mark, a `#!` line - and follows the dash rule: a run of
symbol characters is a line comment only when it is all dashes and at least
two long, so `--|` and `-->` are operators. The parser reads the header and
the import section by Haskell's layout rule: an explicit `{ ; }` block, or the
column of the first declaration, with `;` separating in both. The import
section ends at the first top-level declaration that does not start with
`import`; the rest is kept as tokens. A file without a header is
`module Main (main) where`. `parse` is total: undecodable bytes, a header that
never reaches `where` and an import that is not one are each an opaque island
with no edges and a `LowerError`.

**hspec-discover is read, not run.** A file whose header asks for
`{-# OPTIONS_GHC -F -pgmF hspec-discover #-}` gets an `ImportEdge` to every
file below its directory whose name ends in `Spec.hs` and whose path from
there is a valid module name, which is what `hspec-discover` generates. The
edges are quoted at the pragma.

## Non-goals

- **CPP.** A file with `{-# LANGUAGE CPP #-}`, `-XCPP` or `-cpp` in its header,
  or whose component enables CPP in `default-extensions`, `other-extensions` or
  `ghc-options`, is an opaque island plus a `LowerError` naming it. What CPP
  reads is not Haskell, and a guess at its imports would be reported as fact.
- **Other `-F -pgmF` preprocessors**, in a pragma or a component's
  `ghc-options`: an island plus a `LowerError`, for the same reason.
- **`{-# SOURCE #-}` imports** are plain `ImportEdge`s to the module itself; a
  cycle through one is reported by `no-import-cycles` like any other.
- **`.hs-boot` and literate `.lhs` files** are not discovered.
- **Several packages**, hpack-only and stack-only projects.

## Considered options

- **Hand-parsing the `.cabal` file**, as a first spike did. Rejected: `common`
  stanzas, conditionals and continuation lines are exactly what it got wrong,
  and the real parser is already in GHC's boot packages.
- **`flattenPackageDescription`.** Unions the branches as wanted, but lists
  each kind of component in reverse, which would make the first component on a
  tie the last one written.
- **Bare canonical names, qualified only where two components clash.**
  Shorter Problem ids, but a module's id would change the day another
  component gained a module of the same name, silently orphaning its Baseline
  entries. Qualifying always makes the id a fact of the module alone.
- **One Module per file per component that compiles it.** Truer when two
  components share a source directory, but every Rule over `Deslop/**` would
  then see each module twice. Ownership by the deepest directory is what
  `cabal` projects are laid out for.
- **Reading through CPP** with a default set of macros. Rejected: the result
  depends on flags Deslop does not know, and a wrong edge is worse than a
  warning.

## Consequences

- Deslop checks itself: `deslop/rules/layering.yaml` replaces the `grep`, and
  `just deslop-self` runs in `just check` and in CI.
- How well the frontend reads Haskell is judged against GHC itself
  ([ADR 22](0022-haskell-dependencies-are-judged-against-ghc.md)).
- A project behind CPP gets fewer edges than it has, and is told which files.
- `Frontend.supported` tries TypeScript first, so a repository with both a
  `tsconfig.json` and a `.cabal` file at its root is read as TypeScript.
